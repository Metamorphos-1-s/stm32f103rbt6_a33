# A33 0x0531 面板反馈整合候选

软件基线：`a2174ede65a1927ae491e73289c95bdcaa97deb5`（0x0530）。
编译预设：`Stage5PFeedback`。固件 `0x0531`，Modbus Map `0x0110`。
本报告是软件验证及实板交接，尚未执行烧录或实板验收。

| 操作 | 0x0531 行为 |
| --- | --- |
| 编辑参数时短按 FUNCTION / TARE | 确认到本次菜单会话 / 丢弃当前输入。之前已确认的参数保留。 |
| 列表短按 TARE / 菜单超时 | 有确认的变更就提交一次，没有变更直接返回。超时前尚未确认的输入丢弃；失败时保留候选，不自动重试。 |
| 列表长按 TARE / 长按 FUNCTION | 放弃本次会话 / 保留原保存快捷键。 |
| 选 CAL | 有待提交项时等保存成功及 revision 一致后进入。旧标定跨度超过新 CAP、配置冲突或保存失败都阻止进入。 |
| 称重页置零、去皮及清除 | 成功直接显示重量和相应状态；失败提示保留。标定和恢复出厂仍有独立结果提示。 |
| CAP 和 OL | 隐藏独立 OL。General 采用 CAP＋10×g 分度，Class III Reference 采用原 CAP＋9d。毛重绝对值严格大于 OL 时超载。 |
| 按键及报警声音 | 消抖后一次内置短鸣，约 40 ms。报警输出持续成立时保持鸣叫；按键音不会打断或排队。 |
| 报警区域 | 高级菜单 `ArEA`：`Hi` 原先仅上限外、`oUt` 区间外、`In` 区间内。灯色仍表示 LOW 黄 / OK 绿 / HIGH 红，区间内报警可以绿灯同时鸣叫。 |
| 报警时机 | 高级菜单 `ALArn` 选择 OFF / 实时 / 稳定。`AdLy` 是稳定输出延时，单位 ms，0–10000，步长 100，默认 200。稳定模式仍至少需要 3 个有效新样本，失稳或分类变化重新计时。 |
| 正常判稳 | 新默认保持 300 ms，V3 中原档位默认 1000/500 ms 在 RAM 转为 300 ms，其他保持设置保留。现有短窗加运动检查，共用官方 STABLE；标定判稳及采样/滤波路径不变。 |

取消的是固件写死的 3000 g 上限。出厂 CAP 仍默认 3000 g；读取旧配置时不会删掉既有的额定容量字段。若旧记录中传感器额定容量仍为 3000 g，扩大 CAP 前应先核对铭牌与配置，按实值更正，不能把扩大软件量程当作提高实物承载力。旧 OL 字段只用于保留旧记录布局，BLE 读返回有效值，独立写 OL 会被拒绝。BLE 帧布局未变，新增报警配置通过面板或 Modbus 操作。

| 新增 Modbus 零基地址 | 用途 |
| --- | --- |
| `0x01F1–0x01F4` | 有效 OL，µg，四寄存器，按当前字序，只读 |
| `0x023C` / `0x023D` | Active 报警区域（0/1/2）及稳定输出延时（ms） |
| `0x0253` / `0x0254` | Staging 对应两项；沿用原验证、应用、保存流程 |

V3 可直接读取；启动和无差异保存不会为了升级记录而擦写。发生实际保存时，A/B 机制写入含新报警字段的 schema V4。0x0530 无法读取 V4。回退前必须备份升级前的完整配置区，不能依赖旧固件自动选择正确记录。

软件验证：ARM GNU 13.2.1 Release 构建；BIN 101,628 B，SHA-256
`725F169B4B1A52ABD20677343BE09BF8744D24E09741F014D526F2656BF5B592`。
链接 RAM 19,520 B；静态保守栈碰撞余量 520 B（门槛 512 B），不代表实机水位。
Host Debug 和 Release 回归各 52 项。集成测试覆盖 V3 无写入读取及 V4 重载、5000 g CAP 合法与实际传感器额定保护、超时和 CAL 保存成功/失败、声音优先级、分类变更延时和判稳。
40 Hz / 12 点平均的合成 500 g 阶跃、卸载测试，同一输入旧判据 1450/1450 ms，候选 825/825 ms；单点尖峰没有报稳，合成 0.02 g/s 持续斜坡被识别。真实噪声、慢加料、回零、面板与报警输出仍待实板观察。

## 交给本地 Codex 的实板任务

在明确获得本轮烧录及试验授权后，按下列步骤执行；无烧录授权时只做只读预检。使用 A33 的 COM5 和 SWD，不操作 CH579 固件。

1. 核对仪表上电、COM5、现有固件/Map、revision/saved、活动槽和 CRC。先备份并记录 `0x0801F000–0x0801FFFF` 完整 4096 B 的 SHA-256。核对候选 BIN 的长度和上述 SHA-256。烧录只擦应用页 `[0 123]`，地址 `0x08000000`，读回核对后显式复位。启动后做 FC03 读回并确认配置区字节未变。
2. 在专用测试机上验证 CAP/dP 短按确认、当前编辑短按 TARE 取消、列表短按 TARE 保存、超时混合已确认/未确认两项、长按 TARE 放弃、相同值零写入。比对 revision/sequence；一次有效退出只增加一次。验证 CAP/dP 确认后进入 CAL，观察存储完成才进标定；验证旧标定跨度不合法时保留原配置。未经另行授权不实际完成标定。只在铭牌及标定条件允许时扩大 CAP；不做超额实物加载。
3. 称重页验证短/长 ZERO、TARE，成功返回实际重量，错误提示仍可见。验证按住一个键不重复响；观察报警灯及内外蜂鸣器的区间内/外 × 实时/稳定四组合。记录 0/200/1000 ms 延时，核对失稳、跨限、关闭、故障或样本过期时停止输出。
4. 固定同一传感器和 40 Hz/filt1/strength3 配置，对同一 500 g 砝码做 0x0530/0x0531 各至少三轮加载和卸载对比，采时间戳、原始/滤后重量、STABLE、R5、故障和报警状态，记录面板稳定灯观感。若另外允许慢加料测试，观察约一滴水每秒的加料过程是否提前报稳。记录静置稳定灯是否反复熄灭。未执行项目标为 NOT RUN，不写作通过。
5. 输出报告及原始记录，注明 BIN SHA、配置前后、每项实测状态和恢复方案。若授权回退，0x0530 应搭配升级前的完整 V3 配置区备份；先保存试验后的配置证据。
