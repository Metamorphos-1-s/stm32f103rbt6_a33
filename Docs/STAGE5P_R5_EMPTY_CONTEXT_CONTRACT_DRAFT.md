# R5 已知空载上下文契约草案（未实现）

状态：需求待确定，不能据此烧录或写设备。本草案不分配协议地址/命令号，
不修改 Map 0x010F，不改变现有 ZERO/TARE/标定语义。

## 为什么需要外部上下文

本轮 20/40/80 mg 的机械偏移与真实残留构成逐字节相同的 ADC 输入。
自动恢复旧参考会纠正前者、吞掉后者。触发条件必须来自独立业务事实，
例如 PLC 确认卸料机构完成清空，或操作员明确确认秤台已空。
“stable”“重量接近零”“一个正负配对阶跃”不构成独立事实。

## 可选方案

| 业务条件 | 建议方向 | 能承诺的范围 |
| --- | --- | --- |
| PLC 能确认卸空 | 增加受控的、易失的空载参考捕获/恢复请求 | 在 PLC 断言真实可靠、配置与参考相容时，可研究主动恢复 |
| 只能人工确认 | 独立的人工确认操作，或继续使用既有 ZERO | 人工确认后的处理，不能宣称无人值守自动回零 |
| 必须只靠重量全自动 | 保持真实残留保护，接受回零偏差无法无条件自动消除 | 不承诺同时纠正所有机械偏移并保留所有真实残留 |

## 若选择外部确认，后续实现须满足

1. 先在明确空载时捕获参考，记录当时校准身份、Profile、增益/滤波、tare/runtime-zero
   上下文和 generation。捕获“当时空载重量”不等于把当前重量置成数值零。
   绝对零点误差与一轮装卸后的回零差必须分开验收。
2. 恢复请求必须携带可校验的当前 generation/上下文及明确的外部空载断言。
   没有确认、确认过期或配置变化时拒绝。真实物料存在时不得猜测为空载。
3. DOSING 或加料工艺未结束时拒绝恢复；2/10 秒停顿仍属于加料阶段。
4. 不跳变清空/回填 offset；只在现有幅度与速率上限内研究参考恢复。
   无效样本、fault、overrun、LIMITED 和时间缺口均禁止继续恢复。
5. 参考为易失状态；重启、ZERO/TARE、标定、相关配置变化必须失效或重新验证。
   不把参考写入 Flash，不隐式 SAVE，不覆盖标定。纯 SAVE 连续性须单独核对。
6. 重复请求的处理、失败原因、参考有效性、上下文失配和完成状态应可观察。
   只做诊断结果发布不能暗中修改 revision/saved/dirty；如果还需切换 R5 模式，
   必须沿用现有配置事务语义，不能谎称模式切换不改 revision。
7. 软件门槛至少包含：有/无确认的 20/40/80 mg 残留反例、正负漂移、配置/标定/
   ZERO/TARE/重启/失效确认、重复请求及时间中断。先证明无确认路径保留真实质量，
   再做资源/协议兼容性审查和实板计划。
